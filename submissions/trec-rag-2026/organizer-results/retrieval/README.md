# Understanding Your Retrieval Results

Your team folder contains three **tab-separated (TSV)** files. Open them in a
spreadsheet using **Tab** as the separator. Filter `narrative-id` to **`all`** for
one summary row per run; other rows show individual narratives. `narrative-id` is
the narrative ID, `group` is your team, and `run` is your submission ID.

We evaluate retrieval at two levels: **document relevance using UMBRELA** and
**nugget coverage using gain and effort**.
We evaluate the **full submitted document set**, where **k is the number of
documents submitted for each narrative** and may vary across narratives.

## Document-Level Evaluation: UMBRELA

Document-level evaluation judges each retrieved document's relevance to the
narrative using [UMBRELA](https://arxiv.org/abs/2406.06519)'s automated relevance
judgments generated through RAGDoll. Grades of 2 or higher count as relevant.

| File | Narratives | Metrics |
| --- | --- | --- |
| `retrieval-document-level-scores.tsv` | 82 | `set_P` and `set_recall` at submitted k; `num_ret` (submitted document count, k) |

Document scores were computed with this command using UMBRELA qrels for the
82 evaluation narratives and each run filtered to those narratives:

```bash
trec_eval -q -c -l 2 \
  -m set_P -m set_recall -m num_ret -m num_rel -m num_rel_ret \
  qrels run
```

## Nugget-Level Evaluation: Gain and Effort

Nugget-level evaluation measures how much of the information expected in a
high-quality answer is covered by the retrieved document set.

A **nugget** is a piece of information—a distinct claim or fact—that we expect
a high-quality RAG answer to the narrative to contain, following the
[TREC nugget evaluation methodology](https://arxiv.org/abs/2411.09607).
Vital nuggets are essential to a good answer; okay nuggets add useful but
nonessential information. We measure whether retrieved documents fully
support each nugget. Document-to-nugget assignments are automated for both
nugget collections.

| File | Narratives | Nugget source |
| --- | --- | --- |
| `retrieval-nugget-level-scores-manual.tsv` | 25 | NIST's human-authored nugget rubrics with automatic nugget assignment |
| `retrieval-nugget-level-scores-automatic.tsv` | 25 | Nuggets automatically generated by RAGDoll using the [AutoNuggetizer framework](https://dl.acm.org/doi/abs/10.1145/3726302.3730090), with automatic nugget assignment |

| Column | Meaning |
| --- | --- |
| `gain` | Weight of unique nuggets covered / total nugget weight for the narrative. |
| `effort` | Number of submitted documents, including unassessed documents. |

Higher gain is better. Interpret effort alongside gain: equal gain with fewer
documents means less effort.

Vital nuggets weigh 1; okay nuggets weigh 0.5. Only full support earns credit.

For narrative $t$, let $N_t$ be its nuggets and $C_t$ the unique nuggets fully
supported by at least one submitted document:

$$
\begin{aligned}
\mathrm{gain}_t &= \frac{\sum_{n \in C_t} w_n}{\sum_{n \in N_t} w_n} \\
w_n &= \begin{cases}
1 & \text{vital} \\
0.5 & \text{okay}
\end{cases}
\end{aligned}
$$

**We do not give credit for repetition.** Each nugget counts once across the entire
list. If one document covers A, another repeats A, and a third adds B, the
list covers two nuggets—not three. Repeated information does not reduce gain,
but every document increases effort. A document containing both old and new
nuggets earns additional credit only for the new ones.

We provide [compute_nugget_gain.py](compute_nugget_gain.py) as a reference for
how gain and effort were computed. Its command format is:

```bash
python3 compute_nugget_gain.py -q -c qrels run
```

The nuggets and qrels are not available
for distribution yet, so the script is provided for reference only at this stage.

## Reference Statistics

- **`all`** is an equally weighted narrative average: 82 narratives for document scores,
  25 for either nugget file. Counts in `all` rows are means, not totals.
- For the same run and narrative, `num_ret` and both `effort` values are identical.
  Their overall means can differ because the narrative sets differ. Overall means
  are calculated before narrative scores are rounded.
- **`_min`, `_max`, `_median`** compare all **114 evaluated runs across 27 teams**,
  including yours, with each run weighted equally. They are not team-only
  statistics. In `all` rows, they summarize the runs' overall scores. The median
  averages the two middle values.
